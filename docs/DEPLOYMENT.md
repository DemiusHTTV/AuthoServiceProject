# Развёртывание

## Что поднимается
`docker-compose.yaml` запускает три сервиса:
- `frontend` — Nginx на порту `80`
- `backend` — основной FastAPI на порту `8000`
- `warehouse` — складской FastAPI на порту `8001`

## Требования
- Docker
- Docker Compose
- `uv` нужен только для локальной разработки без контейнеров

## Запуск
Сборка и старт:
```bash
docker-compose up --build
```

Фоновый режим:
```bash
docker-compose up -d --build
```

## Переменные окружения
Сейчас в compose явно используется:
- `WAREHOUSE_URL=http://warehouse:8001`

При локальном запуске без Docker основной сервис по умолчанию использует:
- `WAREHOUSE_URL=http://localhost:8001`

## Хранение данных
В `docker-compose.yaml` объявлены volumes:
- `app_data`
- `warehouse_data`

Важно: в текущем коде пути к SQLite-файлам заданы как:
- `autoservice.db` в корне проекта для основного сервиса
- `warehouse.db` в корне проекта для складского сервиса

Это означает, что конфигурация volumes и пути в коде сейчас описывают данные не полностью согласованно. Для production стоит либо:
- перенести пути БД внутрь смонтированных каталогов
- либо явно смонтировать файлы БД в нужные пути

## Резервное копирование
В текущем состоянии безопаснее бэкапить:
- файл `autoservice.db`
- файл `warehouse.db`
- каталог `data/` с исходными CSV

## Что важно после обновления бонусной логики
- основной сервис хранит историю бонусных операций клиентов в `bonuses`
- при создании заявки могут меняться `bonus_balance` клиента и поля заявки `estimated_price`, `bonus_spent`, `final_price`
- бонусы сотрудников за выполненные задачи сохраняются в `worker_bonuses`
