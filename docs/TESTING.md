# Тестирование

## Текущее состояние
В репозитории есть каталоги:
- `test/unit/`
- `test/smoke/`

Но часть тестов не соответствует текущей реализации проекта:
- встречаются ссылки на старые маршруты
- ожидаются healthcheck-эндпоинты, которых сейчас нет
- в одном smoke-тесте используется несуществующий модуль `wherehouse`
- в `test/unit/` лежит посторонний workspace-файл, не относящийся к тестам

Иными словами, тестовая документация должна отражать, что набор тестов находится в переходном состоянии.

## Что сейчас имеет смысл проверять
- unit-логику библиотеки `autoservice_core`
- ручную проверку основных HTTP-сценариев через `/docs`
- интеграцию основного сервиса со складом при запуске через Docker Compose
- сценарий создания заявки со списанием бонусов

## Запуск тестов
Общий запуск:
```bash
uv run python -m pytest test/
```

Только unit-тесты библиотеки:
```bash
uv run python -m pytest test/unit/test_inventory.py
```

## Что стоит актуализировать дальше
- привести smoke-тесты к реальным маршрутам `/api/clients`, `/api/requests`, `/api/warehouse`
- либо добавить реальные healthcheck-эндпоинты, либо убрать ожидание их наличия
- удалить из `test/unit/` лишние не-тестовые файлы
