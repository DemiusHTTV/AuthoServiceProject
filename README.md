# AutoService Project

Учебный проект сети автосервисов с клиентским веб-интерфейсом, основным FastAPI-бэкендом, отдельным складским микросервисом и общей библиотекой доменной логики.

## О проекте
AutoService моделирует базовые процессы автосервиса:
- регистрацию и авторизацию клиентов
- создание и отслеживание заявок
- работу администратора с заявками и сотрудниками
- рабочее место мастера
- склад запчастей и расчёт стоимости деталей
- бонусную систему для клиентов и сотрудников

## Возможности
- клиент может зарегистрироваться, войти, создать заявку и использовать бонусы
- администратор может принимать заявки, отклонять их, назначать сотрудников и смотреть статистику
- сотрудник может входить в рабочую панель, просматривать задачи и завершать их
- складской сервис хранит запчасти, ищет позиции и рассчитывает стоимость набора деталей
- общая библиотека `autoservice_core` переиспользуется в складской и бонусной логике

## Архитектура
- `frontend/` — статический фронтенд, клиентская логика и локальные assets
- `app/` — основной FastAPI-сервис: клиенты, заявки, админ-панель, рабочие места сотрудников
- `warehouse_service/` — отдельный FastAPI-сервис склада
- `lib/autoservice_core/` — общая библиотека доменных моделей, расчёта стоимости и бонусов
- `data/` — CSV-файлы начального наполнения
- `docs/` — техническая документация
- `test/` — smoke- и unit-тесты

## Быстрый старт
Запуск через Docker:
```bash
docker-compose up --build
```

После старта будут доступны:
- `http://localhost/` — клиентский интерфейс
- `http://localhost/admin` — панель администратора
- `http://localhost/worker` — панель сотрудника
- `http://localhost:8000/docs` — OpenAPI основного сервиса
- `http://localhost:8001/docs` — OpenAPI складского сервиса

## Локальная разработка
Основной сервис:
```bash
uv run uvicorn app.main:app --reload
```

Складской сервис:
```bash
uv run uvicorn warehouse_service.main:app --reload --port 8001
```

Тесты:
```bash
uv run python -m pytest test/
```

## Makefile
Для удобной работы с проектом доступны команды:

| Команда | Описание |
|---|---|
| `make help` | показать список доступных команд |
| `make setup` | установить и синхронизировать зависимости |
| `make run` | запустить основной backend на `8000` |
| `make run-warehouse` | запустить складской сервис на `8001` |
| `make run-all` | запустить оба сервиса |
| `make test` | запустить тесты |
| `make up` | поднять проект через Docker Compose |
| `make down` | остановить Docker Compose |
| `make clean` | удалить локальные базы данных и `__pycache__` |

Основные команды `make` используют скрипты из `scripts/`:
- `scripts/help.sh`
- `scripts/setup.sh`
- `scripts/run-app.sh`
- `scripts/run-tests.sh`

## Структура ролей
- клиентский интерфейс работает через same-origin API
- основной backend отвечает за клиентов, заявки, бонусы и прокси к складу
- складской сервис отвечает за каталог деталей и расчёт стоимости
- библиотека `autoservice_core` содержит общую бизнес-логику
